## 2. What The system is (unchanged from v1)
Multimodal emergency-call **anomaly detector**: the anomaly = a mismatch between **how something is said** (voice emotion) and **what is said** (text content) → signals RISK.
- **ASR** (mHuBERT-147 + LoRA + weighted-sum + CTC + KenLM) → transcript → **text_risk** (BERT zero-shot)
- **SER** (mHuBERT-147 + LoRA + weighted-sum head) → emotion → **voice_risk**
- **Fusion**: combine the two → anomaly.

Both audio models share the **same frozen mHuBERT-147 backbone** (two LoRA adapters + heads). SER status is unchanged from v1 §2b — **do not revisit it**, it is done and reported honestly (UA 59.2 / WA 61.3 six-class; 86.0% as a binary risk detector; val used for both selection and reporting, state that caveat).

### 3a. Findings (all honest, all reportable)
- **Ablation ladder**: the emotion token is worth **1.85–2.56×** what text fine-tuning is worth. This is the headline — the second channel earns its place.
- **The v1 headline was wrong.** v1 appeared to show `late < emotion_only`. That was a class-imbalance + calibration artefact, not a real ordering. Do not repeat the v1 claim.
- **Clean negative result**: training the fusion head under simulated SER noise does **not** recover the **−0.052** deployment cost. Only **2 of 12** cells improved (this line said 18 when it was written; the checkpoint's own `deployment_note` says 12, and p4 is 6 methods × 2 encoders). Explanation: the injected noise is label-independent, so it is irreducible — no amount of noise-aware training removes it. A negative result with a mechanism is worth a slide.
- **SER noise is measured, not invented**: `ser_noise.py` uses the real binary-arousal confusion matrix from `figures/D3_voice_channel.png` (held-out val, n=902).
- **Event drift** across generator models measured at **6.7%**, and shown not to change the ranking. Not a threat to the benchmark.

### 3b. Traps already found — **do NOT re-litigate**
- **Label leakage**: `judge_voice_risk` / `judge_content_risk` are outputs of the *same LLM call* that produced `anomaly`. A 6-cell lookup table on those two columns scores **91.5%**. They are NOT usable as input features. Use `gen_emotion` + `text`.
- **`seed_id` group split is mandatory.** Utterances sharing a seed are near-paraphrases; a row-level split leaks.
- **`seed_universe` must be pinned.** The "filtered" data variant has fewer unique seeds; letting it shuffle its own universe gives it a *different test set* and confounds the ablation. `make_splits(..., seed_universe=<full dataset's seed_ids>)`, plus an assert that filtered-test ⊆ full-test.
- **`compute_metrics` pins `labels=[0,1,2]`** so a model that never predicts `borderline` does not silently misalign the `f1_*` columns.
- **0.4141 is a fingerprint, not a score.** It is exactly emotion-only val macro-F1. If a config reports it, that config has collapsed to ignoring text. FiLM did this in all 21 bert configs until gamma was identity-initialised and text features were mean-centred on train stats.

### 4c. WS-layer finding — real, and it reversed mid-run
```
ep   L7    L8    L9    L10   L11   L12  argmax H/Hmax L9-12
 1  0.105 0.116 0.171 0.228 0.206 0.174  L10   0.980  0.779
 7  0.037 0.064 0.168 0.231 0.313 0.187  L11   0.900  0.899
25  0.013 0.039 0.140 0.157 0.238 0.413  L12   0.812  0.948
```
Mechanism: a *frozen* mHuBERT's layer 12 is specialised toward the pretraining objective and bad for CTC — hence its low initial weight. LoRA adapts it into a task layer and it takes over. Positive feedback: L12's LoRA receives gradient through exactly one path (`w₁₂·h₁₂`), so a larger weight means more adaptation means a larger weight. Lower layers get gradient from many paths and keep training even as their weight falls.

Effective `ws` is now **9,10,11,12** — 94.8% of the mass; L7+L8 hold 5.2%.

**Read `H/Hmax` before the argmax.** `layer_w` is zero-initialised, so the softmax starts perfectly uniform at 1.000. A run ending near 1.000 has selected nothing and its argmax is noise. This is printed every epoch and §12 reads it back from `history.jsonl` for finished runs.

**The `ws=(5,6,7,8)` ablation arm is confounded — do not run it.** If the head only consumes hidden states 5..8, layers 9–12 receive *zero* gradient (the loss does not depend on them). That arm answers "8-layer model vs 12-layer model", not "which layers are best", and wastes 4 layers of forward compute.

**Decision (locked): the 300 h run uses `ws = 9,10,11,12`,** identical to the 100h baseline, so the only thing that changes between the two rows is the data. The WS finding is reported separately as a probe diagnostic.

### 4d. KenLM — same LM as the baseline, tuned decoder
- **LM file is unchanged and must stay unchanged**: OpenSLR-11 `3-gram.pruned.1e-7`, same URL, byte-identical to the baseline's. Swapping it changes the decoder under *both* rows of the results table. `fetch_kenlm.py` refuses to "upgrade" and says why. (For reference: OpenSLR-11 also has an unpruned 3-gram at 759 MB gz and a 4-gram at 1.3 GB gz — the 4-gram's blocker is RAM, not download.)
- Completeness is checked structurally (`\end\` terminator in the last 4 KB), not by size. An earlier 524 MB minimum was simply wrong — the pruned model is ~98 MB — and it deleted a good file.
- **`alpha=0.5, beta=1.0` was hardcoded and never measured**, beam at the pyctcdecode default. `tune_lm.py` (new) fits them.
  - Tuning set is **LibriSpeech dev-other**, deliberately *not* a reported set. Sampled with a fixed stride, because LibriSpeech splits are speaker-ordered and `rows[:500]` would fit alpha to a handful of voices.
  - **ONE** parameter set is applied to **both** reported columns. Tuning per test set would flatter L2-ARCTIC and mean nothing at deployment.
  - Acoustic forward runs once; the grid re-decodes cached log-probs and `reset_params()` avoids reloading the ARPA. 72 grid points instead of 210.
  - Boundary detection: if the best alpha/beta lands on a grid edge it says the grid was too narrow. If best alpha = 0 it says the LM is not helping and to suspect a vocab/normalisation mismatch before believing the result.
  - WER ± SE per grid point; a KenLM gain inside 2 SE is marked `WITHIN NOISE` and must not be reported as a gain.
  - Beam width is **not** chosen by argmin — the smallest beam within 1 SE of the best wins, because beam cost is linear and a noise-sized win should not buy a permanently slower decoder.
  - `lm_params.json` records its `run_dir` and `lm_path`; `eval_asr.py` **refuses** a mismatched file. alpha trades against how well-calibrated a particular acoustic model is and is not transferable between checkpoints.
- **The 100h baseline must be tuned the same way.** Tuning only the 300h model would hand it an unearned advantage. §13 pulls the baseline checkpoint from Drive (`CLEAR/Phase 1/runs/FINAL`) automatically using the OAuth credentials `gdrive_sync.py` already has.

## 7. Bug classes closed — the patterns, so they are not re-introduced

- **"Module written to disk, never invoked."** Hit three times (`gdrive_sync.py`, `eval_asr.py`, `build_cache.py` — the last had no cell that could call it, and the error message told you to "build the manifests first", which was not the problem). An AST check now proves all 10 modules are either subprocess-invoked or imported.
- **Silent swallow.** `except Exception: pass/continue` + reporting only the outcome. Killed the noise banks (§6) and `sync_checkpoint`, which returned `None` for both success and no-op so the caller logged "✓ mirrored" for nothing happening. Every `gdrive_sync` function now returns `(ok, reason)`.
- **`eval_asr.py` once returned hardcoded numbers** (`0.051/0.018/0.083/0.024`). Replaced with a real evaluator; the constants survive only inside a NOTICE comment. If you ever see those four numbers again, something has regressed.
- **One knob doing two jobs.** `batch` scaled both the utterance cap *and* the sampler's seconds budget (`batch × 20 s`), so `batch=64` requested **1280 s of padded audio in one forward pass** while `accum=4` quietly quadrupled the optimisation batch too. Now: `micro_secs` = memory only, `effective_secs` = optimisation only, `accum` derived and un-settable, `effective_secs_actual` recorded in `config.json`. Halving `micro_secs` to fit a card no longer changes the learning-rate-relevant batch.
- **Checks that cannot fail.** The module verifier compared 7 modules against a hardcoded `/6` and reported "All 7/6 modules". Counts now come from one place.
- **Measuring the wrong thing.** `max_memory_allocated` (live tensors, 4.9 GB) is not what nvidia-smi shows (allocator pool, ~42 GB, plus ~0.5 GB context). Both are logged now, and `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` is set before CUDA init to stop length-bucketed batching from fragmenting the pool. Also fixed: KenLM RTF added the *cumulative* forward time each iteration and grew quadratically; `peak_ram_mb` computed `2×peak − current`, which is not a quantity.
- **Grid searches without error bars** pick noise. Every tuned number now carries an SE and a significance verdict.

## 10. Environment notes
- **molab** (marimo cloud), Python 3.13, RTX PRO 6000 (~95 GiB). No CLI — upload the `.py` and it runs as a notebook. No `/content/drive`, so the OAuth path is the one that executes.
- **marimo semantics**: a cell renders its **last expression**; `return` is an export declaration and displays nothing. Building a `layout` and only returning it shows an empty cell. Non-underscore top-level names must be globally unique across cells (`MultipleDefinitionError`).
- **KenLM does not build on molab** → use Colab (Python ≤ 3.12) if you ever need to *build* an LM. Decoding with `pyctcdecode` + a prebuilt ARPA is fine on molab.
- `datasets` v4/v5 removed loading scripts and routes audio decoding through **torchcodec**; `Audio(decode=False)` sidesteps it. `torchaudio` 2.8+ is maintenance-only — `io.AudioEffector` / `apply_codec` are gone, so the telephone-band effect is a plain resample round-trip. `hf_transfer` is deprecated → `HF_XET_HIGH_PERFORMANCE`.
- `torchvision` must match torch (cu128) or transformers crashes with `torchvision::nms`.
- **CTC vocabulary is `A-Z` + apostrophe + `|` + `[UNK]` + `[PAD]` and must NOT be extended** — KenLM was built on LibriSpeech-normalised text. `normalize_text` expands digits to words and drops OOV-character rows for exactly this reason. Emitting a character the LM has never seen collapses the beam search and throws away the 10.1 → 5.1 WER gain.
- Notebooks are self-contained (no cross-imports), Turkish/English mixed comments.
