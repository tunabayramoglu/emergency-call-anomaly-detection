### 1.1 `ablation_engine.py` — the ASR ablation engine

Architecture (fixed from the start, inherited from `sweep_v2.py`):
- **Backbone:** `utter-project/mHuBERT-147`, frozen. Plus LoRA (r=16, α=32,
  q_proj+v_proj, layers 1–12) = **589,824 trainable** parameters.
- **Head:** weighted-sum(layers 9,10,11,12) → 768→768 → ELU → Dropout → 768→30.
  `layer_w` learns which layer to use.
- **Loss:** CTC (blank = `[PAD]`).
- **Data:** LibriSpeech train-clean-100 (28,539 utterances, 100.6 h), dev-clean
  (2,703 utterances). Audio is cached as an int16 memmap; the **cache key is
  identical to `sweep_v2`**, so nothing is decoded twice.

Flow: **BASE** (from scratch) → **X_\<axis\>** (each warm-started from BASE,
independent) → **COMBO** (winners combined). Then **FINAL** by hand (the winning
recipe, from scratch, long).

### 1.2 `train_ser.py` — the SER baseline

- **Data:** CREMA-D (6 emotions) + RAVDESS (8→6 mapping: `calm`→`neutral`,
  `surprised` dropped). Labels are parsed from the filename (the repository
  layout may change, the naming convention does not).
- **Six classes:** neutral, happy, sad, angry, fear, disgust.
- **Backbone:** the frozen *base* mHuBERT-147 — **not** the ASR adapter, see §4.2.
- **The speed idea:** with a frozen backbone and no augmentation, extract
  features **once** and write the mean+std pooling of all 12 layers to disk. The
  head then trains on that small cache — **seconds per epoch**.
- **Head:** weighted-sum(12 layers) → LayerNorm → 1536→256 → ReLU → Dropout(0.3)
  → 6. Class-weighted CE with label smoothing.
- **Metrics:** WA (weighted accuracy) and UA (unweighted / macro recall). UA is
  the more honest one on imbalanced data, so model selection runs on UA.

### 1.3 `kenlm_grid.py` — KenLM decoding

- **Stage 1 (marimo):** `dump_dev_logits(run)` — backbone and head run once and
  write each utterance's **log_softmax** logits plus its reference into
  `dev_logits.npz`.
- **Stage 2 (standalone):** read the npz, install pyctcdecode and a kenlm
  decoder, sweep the α/β grid. No torch or backbone needed.
- **Vocabulary → pyctcdecode:** `|` → space, `[PAD]`/`[UNK]` → blank (`""`).
- If the LM is missing it downloads automatically from OpenSLR
  (`3-gram.pruned.1e-7.arpa`).

## 2. Bugs found and fixed (IMPORTANT — let us not repeat them)

| # | bug | symptom | root cause | fix |
|---|---|---|---|---|
| 1 | **SpecAugment never ran** | no effect whatever `mask_prob` was | an unconditional `backbone.eval()` in the training loop; HF only applies masking while `self.training` | `bb.train() if cfg.bb_train else bb.eval()` |
| 2 | **`max_secs` truncation corrupts the data** | — | audio was cut at 20 s while the transcript stayed complete, so CTC targeted words it never heard | `max_secs=None` (no truncation) plus **frame-budget bucketing** (batches shrink on long utterances, VRAM stays flat) |
| 3 | **VRAM 45→72 GB with an idle GPU** | — | (a) eager attention over 12 layers ≈ 18 GB, (b) random batching wasted 35% on padding, (c) `nw=0` collate ran single-threaded | (a) SDPA, (b) length bucketing, (c) fork-context workers |
| 4 | **DataLoader worker NameError** | `Can't get attribute SpeechDS` | a class defined inside a marimo cell cannot be imported in a spawned worker | `multiprocessing_context="fork"` (inherits memory instead of pickling) plus `probe_workers` |
| 5 | **Head Sequential index shift** | COMBO WER 100%, CER 88% | adding dropout conditionally moved the output Linear between `net.2` and `net.3`; `strict=False` silently skipped it, so the output layer started random | Dropout is now ALWAYS in the stack (p=0 is a no-op), plus a net.2→net.3 remap, and a missing weight now raises a LOUD warning |
| 6 | **EMA warmup** | ema/combo measured the initial weights during the first epochs | decay 0.999 with 112 steps per epoch → EMA is only 11% converged after epoch 1 | `min(decay, (1+t)/(10+t))` warmup |
| 7 | **marimo cell-local names** | `_cell_Xref_load_bank not defined` in the worker | names starting with an underscore are cell-local in marimo and not shared | `_load_bank`→`load_bank`, `_BANKS`→`BANKS` |
| 8 | **`Head.forward` returned None** | `cannot unpack NoneType` | the `return self.net(f), a` line was deleted during an edit | the return was put back |

**The general lesson:** `strict=False` is a silent killer — when the architecture
changes it swallows the weight mismatch and initialises a layer at random. A
critical missing weight now prints a warning.

## 3. Ablation methodology (to be used in the report)

- **Independent axes, not cumulative.** Every axis warm-starts from the same
  BASE. Each contribution is measured in isolation, there is no ordering effect,
  and if the deadline cuts the run short whatever was measured stays valid. COMBO
  is what captures the interactions.
- **`X_control` is mandatory.** It continues from the base with nothing added, on
  the same short budget. Without it, every axis's gain is confounded with "a few
  more epochs of training". The `Δclean` column is measured against **control**,
  not against BASE.
- **The target is the `tel8k/clean` ratio**, not absolute WER. Augmentation's job
  is channel robustness.
- **Augmentation does not move the W/C ratio (WER÷CER)** — only the language
  model does. (Our own phase-1 finding.)
- **KenLM stays OFF throughout the ablation** — it is a constant offset, it does
  not change the ordering, and it costs decoding time. It is enabled once, on the
  winner.
- **Decision rule:** take an axis if it improves the ratio, or improves clean,
  without degrading clean WER by more than 5% relative.

## 4. Results and decisions

### 4.1 Winning axes (greedy, no KenLM)

| axis | what | clean | tel8k | noisy | ratio |
|---|---|---|---|---|---|
| BASE | no augmentation, 35 epochs | 12.28 | 16.29 | 17.25 | 1.33 |
| `bbdrop` | backbone dropout 0.05 | **11.14** | 14.68 | 15.40 | 1.32 |
| `channel` | band + 8k + μ-law | 11.54 | **13.76** | 16.29 | **1.19** |
| `noise` | synthetic pink | 11.59 | 15.34 | **15.03** | 1.32 |
| `rir` | synthetic reverb | 11.41 | 14.78 | 15.76 | 1.30 |
| **combo3** | bbdrop + channel + noise | 11.29 | 13.35 | 14.53 | 1.18 |
| **FINAL** | combo3, 75 epochs from scratch | **10.10** | **11.72** | 14.68 | **1.16** |

### 4.2 What we learned

- **The two augmentation families do different jobs:** representation-level
  (`bbdrop`, `specaug`) lowers clean WER; waveform-level (`channel`) lowers the
  ratio. They are **complementary** — combo3 takes from both.
- **A dropout nuance:** `lora_dropout` is HARMFUL (+0.30 — it suffocates a small
  adapter); `head_dropout` is mild (−0.19); `bb_dropout` is best (−0.86, because
  it behaves like augmentation, acting on the representation rather than the
  parameters). So combo3 uses `bb_dropout` only.
- **The model does not overfit** (frozen backbone, ~1.2M parameters, 100 hours),
  so regularization that limits capacity hurts while representation noise helps.
- **Synthetic pink noise beat the real banks (esc50/urban)** — but the "noisy"
  eval condition is also pink noise, so train–test matching favours pink. On real
  911 audio the banks may well matter (see §7).
- **combo2 was too broad** (8 augmentations); combo3 is leaner (5) and better.
- **The ASR adapter is NOT used for SER:** ASR wants to be invariant to *how*
  something is said — that is exactly what combo3 was trained for — and SER wants
  the opposite. The combo3 adapter suppresses emotional cues. So SER reads from
  the frozen *base* backbone while the ASR adapter stays on the ASR branch. The
  frozen base is shared; the adapters are task-specific.

### 4.3 Open decision

`FINAL` (no head dropout) vs `FINAL_hdo` (`head_dropout=0.05`). Hypothesis: over
50+ epochs, head dropout's contribution may grow beyond the −0.19 seen on a warm
start. Once `FINAL_hdo` finishes, look at clean/ratio/noisy across the four
numbers and decide; KenLM is enabled on the winner ONLY.

## 5. marimo ↔ Google Drive sync

**Why Drive and not HF:** user preference. (The HF push is also set up and
working, as an alternative.) marimo has no native Drive support yet ("coming
soon"; molab persistence currently runs on Cloudflare R2), hence `gdrive_fsspec`
by hand.

**Authentication:**
```python
from gdrive_fsspec import GoogleDriveFileSystem
fs = GoogleDriveFileSystem(use_listings_cache=False, skip_instance_cache=True,
                           auth_kwargs={"use_local_webserver": False})
```
- `use_local_webserver=False` → headless OAuth: it prints a URL, you approve in a
  browser and paste the code back.
- `access_type=offline` plus a refresh token → **once**; afterwards the token is
  cached and it stops asking.
- `use_listings_cache=False` → `fs.exists` does not consult a stale cache but
  asks Drive live, so a just-deleted or just-added file is seen correctly.

**The critical Drive trap:** Drive allows MANY files with the same name in the
same folder (it keys on ID, not name). Depending on the implementation, `fs.put`
may overwrite OR create a duplicate. **We tested it: `put` OVERWRITES and does not
duplicate** → `NEEDS_RM=False`, so no `fs.rm` is needed in the transfer. (To be
sure, we uploaded `_ovtest.txt` twice and counted with `fs.ls`: it appeared once.)

**Path layout:** `REMOTE = "CLEAR/Phase 1/runs"`. Each run goes into its **own
subdirectory**, mirroring the local `runs/` tree exactly:
```
CLEAR/Phase 1/runs/FINAL/{config.json, head.pt, adapter.pt, summary.json, history.jsonl}
CLEAR/Phase 1/runs/combo3/...
```
Files are not dumped flat — every run has a `head.pt`, so the names would collide;
the subdirectory is mandatory.

**Upload rules:**
- Only FINISHED runs — those with a `summary.json` — are uploaded. A run still
  training (FINAL_hdo) is skipped until it finishes.
- `last.pt` is skipped (a few hundred MB, useless outside resuming).
  `head.pt` + `adapter.pt` + metadata come to a few MB.
- `dev_logits.npz` (~350 MB, when present) is uploaded; add it to `skip` if you
  do not want that.
- Re-running is safe: it overwrites and does not accumulate junk.
- **For SER / phase 2:** set `REMOTE = "CLEAR/Phase 2/runs"`; the outputs are in
  `runs_ser/`.

**A warning about embedding this in the overnight runner:** the `fs` object is
defined in a marimo cell, and the overnight flow running in a subprocess cannot
see it. The practical approach is a manual `push_gdrive()` once the runs finish.

## 7. GAPS — what we skipped (for report quality)

None of these block anything right now, but they should be closed for
publication or thesis quality:

1. **A single seed.** Every run used seed=1337. For statistical significance,
   repeat with 2–3 seeds (especially since the combo3 vs channel difference is
   small). At minimum, run FINAL with 2 seeds.
2. **The tel8k/clean ratio contains train–test matching.** We train with
   band+8k+μ-law and measure on tel8k (band+8k). On real 911 audio the gain will
   be smaller. **The clean gain (11.36→10.10) is independent of this caveat** —
   there is no matching there, which makes it the more solid result.
3. **The "noisy" eval is pink noise.** There is no held-out real-noise set. Split
   esc50/urban in half (train on one half, evaluate on the other) to add a
   real-noise condition and honestly measure whether the banks help.
4. **The SER split is not speaker-independent.** The same speaker can land in
   both train and test, which inflates the SER score. Acceptable for a baseline;
   the final number needs a split on CREMA-D/RAVDESS speaker IDs.
5. **Inconsistent batch size.** Some axes ran bs32×8 and others bs64×4. The
   effective batch is 256 either way, so the comparison largely holds, but not
   perfectly. Fix the batch size for the FINAL comparisons.
6. **Old cache vs new cache.** The first X_ axes ran on the truncated cache
   (`max_secs=20`) and FINAL on the untruncated one (`max_secs=None`). Note this
   when comparing; the cleanest fix is to repeat all final comparisons on the
   same cache.
7. **FINAL was still improving slightly at epochs 73–74** — not a full plateau.
   The combo3 recipe might open up a little more at 100 epochs, but returns are
   diminishing.
8. **KenLM normaliser consistency.** Put the reference and the hypothesis through
   the SAME text normaliser (the old benchmark had a "shared normaliser"),
   otherwise WER inflates artificially. `kenlm_grid.py` currently does
   `.upper().strip()`; make sure that matches your jiwer normaliser.
9. **`last.pt` is not on Drive** (deliberately), so the Drive copy CANNOT be
   resumed from — it only has the head and adapter, which is enough for inference
   and warm starts. If you want a full resume, use `skip=()`.
